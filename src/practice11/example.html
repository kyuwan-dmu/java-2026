그 외 (Checked) 일반 예외 · 처리 강제 O (IOException …)

① 예외를 '삼키기' (빈 catch)

실패해도 catch가 아무 일도 안 해서, 사용자는 "성공" 메시지를 받습니다. 진짜 오류가 조용히 사라집니다.

// ❌ 실제로 있던 코드
try {
    sendTempPassword(user);
    msg = "비밀번호를 전송했습니다.";
} catch (Exception e) {
    // 비어 있음 — 아무것도 안 함
}
// ✅ 로그 + 실패를 알림
try {
    sendTempPassword(user);
    msg = "비밀번호를 전송했습니다.";
} catch (MailException e) {
    log.error("전송 실패 id={}", id, e);
    msg = "전송 실패. 다시 시도하세요.";
}

② 오류를 null로 숨기기

호출한 쪽은 null만 받고 '왜' 실패했는지 모릅니다. 주석엔 "로그 출력"이라는데 로그도 없습니다. null은 나중에 NPE로 터집니다.

// ❌ 실제로 있던 코드
try {
    return cancelOrder(orderNo);
} catch (Exception e) {
    return null;   // "로그 출력"이라 써있지만 로그 없음
}
// ✅ 로그 + 의미 있는 예외
try {
    return cancelOrder(orderNo);
} catch (ApiException e) {
    log.error("취소 실패 no={}", orderNo, e);
    throw new OrderCancelException(orderNo, e);
}

③ 너무 광범위한 catch (Exception)

예상한 예외(숫자 변환 실패)뿐 아니라 진짜 버그(NPE 등)까지 잡아 숨깁니다. 잡을 것만 구체적으로 잡으세요.

// ❌ 버그까지 다 삼킨다
try {
    int price = Integer.parseInt(s);
} catch (Exception e) {   // NPE까지 잡힘
    price = 0;
}
// ✅ 예상하는 예외만
try {
    int price = Integer.parseInt(s);
} catch (NumberFormatException e) {
    price = 0;
}

④ (상황에 따라 OK) close() 삼키기 → try-with-resources

자원 닫기라 봐주지만 반복되고 지저분합니다. 데모 4번의 try-with-resources로 통째로 없앨 수 있습니다.

// △ 자원 닫기 삼키기
} finally {
    try { workbook.close(); }
    catch (Exception ignore) {}
}
// ✅ 자동 close
try (Workbook wb = create()) {
    // ... 사용 ...
}   // close() 자동 호출
